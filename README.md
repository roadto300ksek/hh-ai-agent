# Мультиагентная система автоматизации поиска и первичного отбора (AI-агент)

Учебный пет-проект, демонстрирующий навыки автоматизации бизнес-процессов с использованием Python и LLM.

## 🎯 Задача
Автоматизировать рутинный процесс: сбор данных (вакансий), их семантический анализ, генерацию персонализированных текстов и выполнение целевых действий в браузере.

## 🧠 Архитектура

**Агенты (CLI):**
1. **`hh_login.py`** — авторизация и сохранение сессии (cookies).
2. **`hh_scanner_multi.py`** — сканер. Playwright + фильтры поиска (регион, опыт, удалёнка, пагинация) на стороне hh.ru.
3. **`hh_analyzer.py`** — аналитик. LLM (DeepSeek) оценивает релевантность 0-100; при сбое пачка не теряется.
4. **`hh_writer.py`** — копирайтер. Уникальные письма под вакансию; неотправленные письма переживают перезапуск.
5. **`hh_executor.py`** — исполнитель. Отклики с паузами, автоматические ответы на вопросы работодателя, сопроводительное письмо через форму или чат, **автоматический выбор резюме по вакансии**, повторные попытки и дневной лимит.

**Общий слой:**
* `config.py` — профиль кандидата, вызов LLM с retry/backoff и таймаутом.
* `database.py` — SQLite: отправленные отклики, ручная очередь, дневная статистика.
* `paths.py` — абсолютные пути (скрипты не зависят от текущей папки).
* `utils.py` — безопасная запись JSON, проверки видимости элементов, логи.
* `hh_browser.py` — единая настройка Playwright для всех агентов.
* `app.py` — Streamlit-дашборд: метрики, отклики с фильтрами и выбранным резюме, очередь писем, список резюме, ручная очередь, кнопки ручного запуска агентов и живой лог.

Запуск: `streamlit run app.py` → http://localhost:8501. Дашборд читает SQLite и локальные JSON, ничего не отправляет без нажатия кнопки.

Управление — только через дашборд: `streamlit run app.py` → http://localhost:8501. Отдельные этапы при необходимости запускаются вручную (`hh_login.py`, `hh_scanner_multi.py`, `hh_analyzer.py`), но все действия агента — отправка откликов, генерация писем, отбор активных вакансий и обновление резюме — находятся во вкладке «🚀 Запуск»: выберите действие и нажмите «▶️ Запустить».

Полезные ручные режимы:

* `python hh_active_filter.py --headless --top 100` — проверить вакансии через Playwright и сохранить только активные в `active_candidates.json` (исключает архив, уже отправленные и вакансии без кнопки отклика).
* `python hh_writer.py --input active_candidates.json --limit 20 --min-score 0` — писать письма по заранее отобранному списку вакансий.
* `python hh_writer.py --input active.json --limit 20 --min-score 0` — писать письма по произвольному файлу вакансий.
* `python hh_executor.py --headless --limit 10 --min-delay 90 --max-delay 180` — отправить пачку с короткими паузами. Значения по умолчанию: 5–15 минут между откликами; те же параметры есть в дашборде.

## 📄 Data-Driven резюме (v2.0)

Отдельная ветка пайплайна: собрать полные описания вакансий, понять рынок и сгенерировать 10 честных вариантов резюме под разные категории. Запускается вручную, не привязана к автоматическим запускам.

Порядок:
1. `python hh_scanner_multi.py` — собрать вакансии в `vacancies.json` (как обычно).
2. `python hh_details_collector.py --limit 300` — открыть вакансии через Playwright и сохранить полные описания в `vacancy_details.json`. Уже собранные ссылки пропускаются, прогресс пишется после каждой вакансии. Если часть страниц не отдала описание, повтори: `python hh_details_collector.py --retry-empty`.
3. `python hh_market_analyzer.py` — батчами через LLM извлечь названия должностей, навыки, софт-требования и боли работодателей; результат в `market_trends.json`.
4. `python build_user_profile.py` — собрать `user_real_profile.json` из `candidate_local.py`: единственный источник фактов для резюме.
5. `python hh_resume_targeter.py` — определить 10 целевых категорий вакансий; результат в `resume_targets.json`.
6. `python hh_resume_generator.py` — сгенерировать 10 резюме: `generated_resumes.json` для автоотбора и `resumes.md` для ручного копирования на hh.ru.
7. `python hh_resume_filler.py --all` — создать резюме на hh.ru автоматически: дублирует базовое резюме, задаёт уникальную должность и специализации, заполняет «О себе» и навыки, проверяет результат. Хэши сохраняются в `hh_created_resumes.json` (тоже в `.gitignore`). Полезные режимы: `--list`, `--ids ai,qa`, `--id bots`, `--headless`, `--hash <хэш>` (наполнить существующее резюме), `--all --update` (обновить тексты у уже созданных).

Проверка на выдумки: навыки вне профиля отбрасываются, `about` обрезается до 1000 символов, запрещённые утверждения (`5 лет опыта`, `коммерческий опыт в IT`, `Middle` и т.п.) блокируются.

Все файлы этого этапа (`vacancy_details.json`, `market_trends.json`, `user_real_profile.json`, `resume_targets.json`, `generated_resumes.json`, `resumes.md`, `hh_created_resumes.json`) содержат личные данные и добавлены в `.gitignore`.

## 🎯 Автовыбор резюме при отклике (этап 5)

`hh_resume_selector.py` детерминированно подбирает одно из 10 резюме под вакансию — без LLM, поэтому результат можно проверить и объяснить:

* сильные сигналы в названии (`QA`, `Telegram`, `парсинг`, `LLM`, `RPA`, `ETL`, `API` и т.п.) выбирают категорию;
* если сигналов в названии нет, категория выбирается только при 2+ сигналах в описании;
* если сигналов нет вообще — используется `general`;
* фразы из `generated_resumes.json` (`target_titles`, `match_keywords`) добавляют очки и разбивают ничьи.

Проверить вручную: `python hh_resume_selector.py --title "QA Automation Engineer (Python)"` или `python hh_resume_selector.py --file analyzed_vacancies.json --limit 20`.

`hh_executor.py` выбирает резюме перед отправкой, меняет его в модалке/на странице отклика и сохраняет `resume_id` в базе (`sent_applications.resume_id`, колонка добавляется миграцией).

## 🛠 Стек технологий
* **Язык:** Python 3
* **Автоматизация браузера:** Playwright
* **Работа с LLM:** OpenAI SDK (DeepSeek API), JSON-режим, retry с backoff
* **Хранение:** SQLite (WAL, UPSERT статусов)
* **Форматы данных:** JSON (обмен между агентами)
* **Интерфейс:** Streamlit
* **Тесты:** unittest (без внешних зависимостей)
* **Парсинг:** DOM-селекторы (Playwright)

## 🚀 Результаты
* Один прогон обрабатывает **460+ карточек** данных.
* ИИ-фильтр отсеивает **75% нерелевантного мусора**.
* Время на рутину сокращено с 3-4 часов до 15 минут в день.

## ⚙️ Установка и запуск
1. Установите зависимости: `pip install -r requirements.txt`
2. Установите браузеры: `playwright install`
3. Создайте файл `.env` в корне проекта и добавьте ключ:
   ```
   DEEPSEEK_API_KEY=ваш_ключ
   ```
4. Запустите вход: `python hh_login.py` (сессия сохранится в `hh_state.json`).
5. Дальше управляйте через дашборд: `streamlit run app.py`. Во вкладке «🚀 Запуск» выберите действие и нажмите «▶️ Запустить»; там же в раскрышке «Настройки» живут лимиты, паузы и источник вакансий. Сканер (`hh_scanner_multi.py`) и анализатор (`hh_analyzer.py`) запускаются отдельно по мере необходимости.

Тесты: `python -m unittest discover -s tests -t . -v`

### Настройки
* `hh_scanner_multi.py` — `SEARCH_QUERIES`, `SEARCH_FILTERS` (регион, опыт, формат работы), `SEARCH_PAGES`.
* `hh_analyzer.py` — `BATCH_SIZE`, профиль кандидата в `config.py`.
* `hh_writer.py` — `TOP_N` (сколько новых писем за запуск).
* `hh_executor.py` — `DAILY_LIMIT` (учитывает уже отправленные сегодня), паузы между откликами.

### Личные данные
В GitHub лежат только заглушки. Личные данные (имя, город, контакты, зарплата, образование, GitHub) хранятся локально:

1. Скопируйте `candidate_local.example.py` в `candidate_local.py`.
2. Заполните свои данные в `CANDIDATE_PROFILE`, `CANDIDATE_INFO` и `CANDIDATE_ANSWERS`.
3. `candidate_local.py` уже добавлен в `.gitignore` и не попадёт в репозиторий.

`config.py` автоматически подхватывает `candidate_local.py`, если он существует. Без него проект работает с заглушками.

### Устойчивость
* Пустая выдача сканера не затирает предыдущий `vacancies.json`.
* Если LLM не ответил ни по одной вакансии, старый `analyzed_vacancies.json` сохраняется.
* Битый `cover_letters.json` откладывается в `.broken-*`, запуск продолжается.
* JSON пишется атомарно — при остановке не остается полуфайл.
* Статус отклика проверяется по видимым элементам, а не по `count() > 0`.

### Автоответы на вопросы и письма
* Если у вакансии есть анкета работодателя, исполнитель отвечает на вопросы через DeepSeek по фактам из `config.py` (`CANDIDATE_ANSWER_RULES`) и сам заполняет форму.
* Письмо вставляется в форму отклика. Если hh.ru отправляет отклик сразу, письмо добавляется через чат отклика.
* Если письмо не подтвердилось, делается до 3 попыток, затем fallback по Enter, а в конце запуска — повторный проход по сегодняшним `no_letter`.
* Если отклик уже был отправлен раньше, исполнитель открывает чат и прикрепляет письмо, если его там ещё нет.
* Статус `sent` ставится только после подтверждения: письмо видно в переписке или отклик подтверждён hh.ru.
* Чтобы изменить ответы на вопросы, отредактируйте `CANDIDATE_ANSWER_RULES` в `config.py`.

## ⚠️ Ограничения
* Проект создан в учебных целях. Автоматические отклики нарушают правила hh.ru и могут привести к блокировке аккаунта. Для демонстрации используйте тестовый аккаунт/моковый стенд.
* Селекторы hh.ru меняются: при поломке парсинга запустите `hh_debug.py` и обновите селекторы.
* Капча: интерактивно — ждёт Enter в консоли; из дашборда — запрос пропускается без блокировки пайплайна.
