# Мультиагентная система автоматизации поиска и первичного отбора (AI-агент)

Учебный пет-проект, демонстрирующий навыки автоматизации бизнес-процессов с использованием Python и LLM.

## 🎯 Задача
Автоматизировать рутинный процесс: сбор данных (вакансий), их семантический анализ, генерацию персонализированных текстов и выполнение целевых действий в браузере.

## 🧠 Архитектура

**Агенты (CLI):**
1. **`hh_login.py`** — авторизация и сохранение сессии (cookies).
2. **`hh_scanner_multi.py`** — сканер. Playwright + фильтры поиска (регион, опыт, удалёнка, пагинация) на стороне hh.ru.
3. **`hh_analyzer.py`** — аналитик. LLM (DeepSeek) оценивает релевантность 0-100; при сбое пачка не теряется.
4. **`hh_writer.py`** — копирайтер. Уникальные письма под вакансию; неотправленные письма переживают перезапуск.
5. **`hh_executor.py`** — исполнитель. Отклики с паузами, проверкой результата и дневным лимитом.

**Общий слой:**
* `config.py` — профиль кандидата, вызов LLM с retry/backoff и таймаутом.
* `database.py` — SQLite: отправленные отклики, ручная очередь, дневная статистика.
* `paths.py` — абсолютные пути (скрипты не зависят от текущей папки).
* `utils.py` — безопасная запись JSON, проверки видимости элементов, логи.
* `hh_browser.py` — единая настройка Playwright для всех агентов.
* `app.py` — Streamlit-дашборд: статистика, очередь, лог запуска, запуск пайплайна.

Pipeline: `hh_login.py` (один раз или при протухшей сессии) → `run_all.py` (scanner → analyzer → writer → executor).

## 🛠 Стек технологий
* **Язык:** Python 3
* **Автоматизация браузера:** Playwright
* **Работа с LLM:** OpenAI SDK (DeepSeek API), JSON-режим, retry с backoff
* **Хранение:** SQLite (WAL, UPSERT статусов)
* **Форматы данных:** JSON (обмен между агентами)
* **Интерфейс:** Streamlit
* **Тесты:** unittest (без внешних зависимостей)
* **Парсинг:** DOM-селекторы (Playwright)

## 🚀 Результаты
* Один прогон обрабатывает **460+ карточек** данных.
* ИИ-фильтр отсеивает **75% нерелевантного мусора**.
* Время на рутину сокращено с 3-4 часов до 15 минут в день.

## ⚙️ Установка и запуск
1. Установите зависимости: `pip install -r requirements.txt`
2. Установите браузеры: `playwright install`
3. Создайте файл `.env` в корне проекта и добавьте ключ:
   ```
   DEEPSEEK_API_KEY=ваш_ключ
   ```
4. Запустите вход: `python hh_login.py` (сессия сохранится в `hh_state.json`).
5. Запустите полный цикл: `python run_all.py` или по шагам: `hh_scanner_multi.py` → `hh_analyzer.py` → `hh_writer.py` → `hh_executor.py`.

Дашборд: `streamlit run app.py` (запуск пайплайна, статистика, лог).

Тесты: `python -m unittest discover -s tests -t . -v`

### Настройки
* `hh_scanner_multi.py` — `SEARCH_QUERIES`, `SEARCH_FILTERS` (регион, опыт, формат работы), `SEARCH_PAGES`.
* `hh_analyzer.py` — `BATCH_SIZE`, профиль кандидата в `config.py`.
* `hh_writer.py` — `TOP_N` (сколько новых писем за запуск).
* `hh_executor.py` — `DAILY_LIMIT` (учитывает уже отправленные сегодня), паузы между откликами.

### Устойчивость
* Пустая выдача сканера не затирает предыдущий `vacancies.json`.
* Если LLM не ответил ни по одной вакансии, старый `analyzed_vacancies.json` сохраняется.
* Битый `cover_letters.json` откладывается в `.broken-*`, запуск продолжается.
* JSON пишется атомарно — при остановке не остается полуфайл.
* Статус отклика проверяется по видимым элементам, а не по `count() > 0`.

## ⚠️ Ограничения
* Проект создан в учебных целях. Автоматические отклики нарушают правила hh.ru и могут привести к блокировке аккаунта. Для демонстрации используйте тестовый аккаунт/моковый стенд.
* Селекторы hh.ru меняются: при поломке парсинга запустите `hh_debug.py` и обновите селекторы.
* Капча: интерактивно — ждёт Enter в консоли; из дашборда — запрос пропускается без блокировки пайплайна.
